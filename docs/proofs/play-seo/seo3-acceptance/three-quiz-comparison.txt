Preconditions (all computed inside the shipped code):
  playsDisplay = extra.totalPlaysWithScore > 0
               ? extra.totalPlaysWithScore
               : quiz.play_count
             = 2060                                  (R3 + C1)
  scoresUnlocked = playsDisplay >= RANKING_UNLOCK_VOTES(30)
                = true                               (C2)
  passRate     = round(extra.passingPlays / extra.totalPlaysWithScore * 100)
              = round(665 / 2060 * 100)
              = 32                                   (C3)
  introAvg     = round((total_score_sum / total_completions) / questionCount * 100)
              = 53
  intro branch = plays >= 1000 -> D
  D sub-branch = perfect > 0 AND introAvg < 60 -> first arm

===========================================================
Why these three pages still read genuinely differently
===========================================================
Chrome is shared (breadcrumb, player, hall of fame, related list,
article links, JSON-LD wrapper). Everything else is per-quiz real
data:

  - Intro:     three DIFFERENT branches (D / C / B). Different lengths,
               different phrasings, different embedded numbers.
  - Cells:     BIG and MID render 6 cells with the ranking-ish trio
               visible. TINY renders 2 cells and a gate line - the
               HTML is materially different from the other two.
  - Numbers:   every value (2060 / 853 / 5, 53 / 57 / gated, 224 / 62
               / 2, 32% / 36% / gated, 18s / 41s / gated) is unique
               to the quiz.
  - JSON-LD:   BIG and MID emit Complete+Like counters; TINY emits
               Complete only (likes=0, no Like counter). hasPart
               varies in length (8/20/10 Question entities).
