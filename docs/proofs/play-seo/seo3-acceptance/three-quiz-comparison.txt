Why these four pages still read genuinely differently
===========================================================
Chrome is shared (breadcrumb, player, hall of fame, related list,
article links, JSON-LD wrapper). Everything else is per-quiz real
data:

  - Intro:     four DIFFERENT rendered shapes fire across the four
               tiers (D / C / B / B-no-avg for the clue quiz).
               Different lengths, different phrasings, different
               embedded numbers.
  - Cells:     BIG and MID render 6 cells with the ranking-ish trio
               visible. TINY renders 2 cells and a gate line. CLUE
               renders 1-2 cells and NO gate line (the type-suppressed
               metrics have no unlock). HTML shape is materially
               different across all four.
  - Numbers:   every value (2060 / 853 / 5 / 7, plus 53 / 57 / gated /
               gated, 224 / 62 / 2 / suppressed, 32% / 36% / gated /
               suppressed, 18s / 41s / gated / suppressed) is unique
               to the quiz or genuinely absent for a real reason.
  - JSON-LD:   BIG and MID emit Complete+Like counters; TINY emits
               Complete only (likes=0, no Like counter); CLUE emits
               a Play counter only when plays=7. hasPart varies in
               length (8 / 20 / 10 / 10 Question entities).

C4 correctness verification
===========================
The score-derived cells and the intro's score-derived tokens flow
through ONE named predicate, `scoreIsPerQuestion(quizType)` in
apps/quiz/src/lib/quiz/scoring.ts. The allowlist:

  multiple_choice   -> per-question (1 point / question)
  true_false        -> per-question
  image             -> per-question
  intruder          -> per-question
  guess_from_clues  -> NOT per-question (multi-point by speed)

Deny by default. A new quiz type must OPT IN in that file. Any consumer
that forgets the gate is a bug: use the helper, do not re-implement.
