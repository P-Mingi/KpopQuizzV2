# Launch runbook: OtakuQuiz (otakuquiz.org) and FanQuiz (fanquiz.org) with kpopquiz.org (run O1, lane L1)

For the owner. Every production step is yours; no agent runs anything against production. Companion files, all in this folder:
`SQL-ORDER.md` (every SQL file in apply order), `ENV.md` (every variable per project), `VERIFY.md` (read-only checks, V0 to V11),
`ROLLBACK.md` (the way back, and when it stops being possible). Content SQL is generated by `apps/quiz/e2e/o1/L1/content-sql.mjs`.

Written 2026-10-21 from `o1/integration` (lots a to d merged, lot e partly). Steps that depend on lot (e) lane B7 (emails, account
deletion, SQL 016, `L03-B7-sentinel`) are marked **B7, to confirm when merged**: they come from `docs/o1/contracts/` and
`docs/o1/briefs/B7.md`, not from merged code.

## 0. How to read a step

    Step ID  Title
    Who:     owner (always)
    Do:      the command or the dashboard path
    Check:   the proof it worked (a V number of VERIFY.md, with the expected result)
    Back:    the way to undo it (ROLLBACK.md has the long form)

- Times are UTC. Daily crons fire at 00:05 (`ensure-daily-quiz`), 00:10, 00:12 (anime opening), 00:20, 03:30, 03:40, 03:50, 03:55, 04:00, 04:15, 05:00,
  every 15 minutes (`editorial-publish`) and every 30 minutes (`live-expire`). Avoid 23:50 to 00:30 for anything that touches `quizzes`, `quiz_bank` or `qotd_log`.
  Do the SQL steps in your quietest hour; `lock_timeout` makes a file fail instead of waiting, and every file can simply be run again.
- T0 is the launch day. The dates below are the latest ones; earlier is fine. If a step fails and the cause is not obvious, stop at that step
  (the state after any finished step is safe to stay in for days) and read the file's header.
- Keep a plain text log of your own, one line per step: time, step ID, file, result. `docs/o1/migration-log.md` is for the dev branches only.
- Shell helpers (once per terminal; the connection string is typed, never saved):

      read -rs PROD_DB_URL; export PROD_DB_URL
      M=docs/pending-migrations/multisite
      sql1() { psql "$PROD_DB_URL" -X -v ON_ERROR_STOP=1 --single-transaction -f "$1"; }
      sqln() { psql "$PROD_DB_URL" -X -v ON_ERROR_STOP=1 -f "$1"; }
      q()    { psql "$PROD_DB_URL" -X -At -v ON_ERROR_STOP=1 -c "$1"; }

  Work from the repository root with `main` checked out after the merge (A5). `psql` 15 or later.
