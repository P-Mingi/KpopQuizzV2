# Launch runbook: Bunnyverse (bunnyverse.org, with OtakuQuiz at /anime) next to kpopquiz.org (run O1)

For the owner. Every production change is yours; agents only read production (owner decision 2026-10-28: Claude, the integrator, runs the
read-only SQL checks and reads the Supabase logs, a worker runs the HTTP checks and reads Vercel). One exception, 2026-10-28: the integrator set the
Vercel variables and created the Microfrontends group with the CLI (`ENV.md` marks the variables). Companion files, all in this folder: `OWNER-NOW.md`
(in French: every action in order, who does it, and the lines to copy), `SQL-ORDER.md` (every SQL file in apply order), `ENV.md` (every variable per project), `VERIFY.md` (read-only checks,
V0 to V11), `ROLLBACK.md` (the way back, and when it stops being possible), `OWNER-TODO.md` (status, totals, decisions).
Content SQL is generated by `apps/quiz/e2e/o1/L1/content-sql.mjs`. `apps/quiz/e2e/o1/L1/runbook-paths.sh` proves every file this kit names exists.

Rewritten on 2026-10-28 for the owner's Bunnyverse decisions (section "Owner decisions" at the end):
- One new domain, `bunnyverse.org`, with sub-folders. `https://bunnyverse.org` is the Bunnyverse hub (site id `hub`, Vercel project
  `fandomverse`, renamed from `fanquiz`). `https://bunnyverse.org/anime` is OtakuQuiz (site id `anime`, Vercel project `otakuquiz`), served on the
  same origin by Vercel Microfrontends: a group `fandomverse`, default app `fandomverse`, child app `otakuquiz` routing `/anime` and `/anime/:path*`.
  The `otakuquiz` project never gets a domain. kpopquiz.org (Vercel project `kpopquiz`) stays separate and unchanged.
- Sign-in on bunnyverse.org: Google (the kpopquiz.org Google client) and Discord, no email. The hub and `/anime` share one session (same origin).
  Between kpopquiz.org and bunnyverse.org the passport ticket (`PASSPORT_JUMP`) stays.
- No calendar. Each phase starts as soon as the one before is clean. Watches: 24 hours after B (001 to 007), 24 hours after 008 (D3) and
  24 hours after 010 (F). A backup (A2) at the start of every SQL session.
- What the sub-folder layout means in this kit: every OtakuQuiz path starts with `/anime` (pages, `/anime/api/...`, `/anime/sitemap.xml`);
  any other path on bunnyverse.org is the hub. The code lanes describe the layout in ARCHITECTURE-BUNNYVERSE.md and the sign-in in
  AUTH-BUNNYVERSE.md (lane 3), both in this folder once their lanes are merged. Where they say something else than this kit, they win.

## 0. How to read a step

    Step ID  Title
    Who:     owner for the Do; Claude or a worker for the Check (read-only)
    Do:      the command or the dashboard path
    Check:   the proof it worked (a V number of VERIFY.md, with the expected result)
    Back:    the way to undo it (ROLLBACK.md has the long form)

- Who (owner decision 2026-10-28): the owner runs no check command. Claude runs the read-only SQL and reads the Supabase logs; a worker runs the curl
  checks and reads Vercel. The live proofs with a real account (B5, B7, D2, D3, K6, K7, K9) stay the owner's: no agent signs in or creates an account in production.
- Times are UTC. The crons are the `crons` list of `apps/quiz/vercel.json` (18 entries on 2026-10-28). Daily ones fire at 00:05 (`ensure-daily-quiz`), 00:10, 00:20,
  03:30, 03:40, 03:50, 03:55, 04:00, 04:15, 05:00 and 09:30; `editorial-publish` every 15 minutes, `live-expire` every 30 minutes; the rest weekly or monthly.
  Never run SQL between 23:50 and 00:30. Do the SQL steps in your quietest hour; `lock_timeout` makes a file fail instead of waiting,
  and every file can simply be run again.
- No dates. The table below says what each phase waits for. If a step fails and the cause is not obvious, stop at that step
  (the state after any finished step is safe to stay in for days) and read the file's header.
- Keep a plain text log of your own, one line per step: time, step ID, file, result. `docs/o1/migration-log.md` is for the dev branches only.
- Shell helpers (once per terminal; the connection string is typed, never saved):

      export PATH="/opt/homebrew/opt/postgresql@18/bin:$PATH"
      read -rs PROD_DB_URL; export PROD_DB_URL
      M=docs/pending-migrations/multisite
      sql1() { psql "$PROD_DB_URL" -X -v ON_ERROR_STOP=1 --single-transaction -f "$1"; }
      sqln() { psql "$PROD_DB_URL" -X -v ON_ERROR_STOP=1 -f "$1"; }
      q()    { psql "$PROD_DB_URL" -X -At -v ON_ERROR_STOP=1 -c "$1"; }

  Work from the repository root with `main` checked out after the merge (A5). `psql` and `pg_dump` 15 or later: on the owner's Mac the default `psql` is 14,
  the PATH line puts the Homebrew PostgreSQL 18 tools first (`A1-A3.sh` does the same); `psql --version` must then print 18. `snap` is in VERIFY V1.
  `read -rs` shows nothing while you paste; press return. The RUNBOOK's blocks carry no `#` comments on purpose: zsh, the macOS shell, passes them as arguments unless `interactivecomments` is set.
