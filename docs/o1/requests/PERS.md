3. `docs/o1/contracts/schema.sql` (F0/B2/O5). `personality_questions` has no group column and a unique index on `ord` alone, and the contract adds none. PERS stores
   the eight questions of a series at `ord = groups.id * 12 + 1 to groups.id * 12 + 8` (site anime; `ord` is a smallint, so a group id up to 2730; the load stops
   with a message beyond it, or when a question of another site sits in the band). It needs no DDL and works on o1-dev and production as they are. The clean form,
   when a migration is allowed: `alter table public.personality_questions add column group_id integer references public.groups(id) on delete cascade;`, drop
   `idx_personality_questions_ord`, `create unique index on public.personality_questions (site_id, coalesce(group_id, 0), ord);`, set `group_id = ord / 12` for the
   anime rows. Then `questionBand()` (lib/personality/parse.ts) becomes `.eq('group_id', ...)` and `ordOf()` (scripts/anime/k1/personality-data.mjs) the plain `n`.
