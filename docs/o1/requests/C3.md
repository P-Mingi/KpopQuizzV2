# Requests of C3 (files C3 does not own)

C3 changed only `apps/quiz/src/**`, its e2e report and this file. Four changes touch files owned by others; each is a ready patch
below (`git apply` from the repo root). Order: 1 and 2 together (the contract test compares the flag table with `O1_FLAGS`), 3, 4 alone.

1. `docs/o1/contracts/flags-env.md`, `LANES.md` (owner F0/L1) and `apps/quiz/src/lib/site/registry.ts`: register the new server flag
   `NET_INDEXING` (read by `apps/quiz/src/lib/site/indexing.ts`, default off = every page of anime and hub is noindex, nofollow).
   Registry line to add after PASSPORT_SEED in `O1_FLAGS`: `{ name: 'NET_INDEXING', scope: 'server', lane: 'L1', reserved: false },`
2. `apps/quiz/next.config.ts` (owner ORCH): the `X-Robots-Tag: noindex, nofollow` header on every answer of a closed anime or hub build
   except /robots.txt and /sitemap.xml (the meta tag already closes every HTML page; the header covers images, JSON and PDFs). kpop never
   gets the entry. Test for it (add to `apps/quiz/src/lib/site/indexing.test.ts`): import `next.config` with NET_INDEXING unset and `NEXT_PUBLIC_SITE_ID=anime` or `hub`, expect one header rule whose source regex rejects /robots.txt and /sitemap.xml and accepts /q/x; with NET_INDEXING=1, or on kpop, expect none.
3. `docs/o1/contracts/routes.md` line 209: the hub sitemap lists `/` only, because `/privacy` of the hub is a noindex draft (a noindex URL
   must not be in a sitemap). Code and tests are already changed in C3 (`root-files.ts`, `root-files.test.ts`).
4. `apps/quiz/e2e/o1/C1/a11y.o1.ts` (owner C1): the dark mode axe pass sampled colours in the middle of the 250 ms background fade of
   `.ux-app` (a0.css), so under load it failed with a different contrast count each run (x19, x18, a login page); switch transitions
   off for the sample. Spec result with the patch: 6 passed, 4 skipped (the signed-in tests, which need dev-up's sign-in helper).
