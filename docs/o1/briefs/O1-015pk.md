## The defect
public.spoiler_reports has primary key (quiz_id, reporter_id) with foreign keys to quizzes and profiles, so PostgREST treats it as a
many-to-many junction: every embed between quizzes and profiles becomes ambiguous (PGRST201). On o1-dev it made quiz pages 404 even on the
kpop build; in production it would break kpopquiz.org the day 015 is applied. C1 added foreign-key hints to the embeds it saw; the root
cause must go.
## Fix
- 015: spoiler_reports gets `id bigint generated always as identity primary key` and `unique (quiz_id, reporter_id)` (constraint
  spoiler_reports_quiz_reporter_key); report_spoiler's conflict target follows. Idempotent: on a database where 015's earlier version is
  applied, convert in place (drop the old primary key, add the column and the new keys) without losing rows. Rollback updated.
- Apply on o1-scratch (S/env.sh scratch -- bash -c '/opt/homebrew/opt/postgresql@18/bin/psql "$O1_DB_URL" -v ON_ERROR_STOP=1 -f <file>')
  twice, rollback, re-apply; apps/quiz/e2e/o1/O1/spoiler-reports.sh passes; then the same apply on o1-dev (S/env.sh dev, same command).
- Proof against PostgREST on o1-dev: a request with the anon key through S/env.sh dev (never print the key or URL) for
  /rest/v1/quizzes?select=id,profiles(username)&limit=1 answers 200 (no PGRST201). Keep C1's hints.
