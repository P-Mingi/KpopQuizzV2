## Spike findings (branch o1/F0s)

1. **beforeFiles rewrites chain.** Next applies every beforeFiles rule in sequence, each once, on the path the
   previous rules left, with no filesystem check in between (`filesystem.js` gives `before_files_rewrite` routes no
   `check`). Measured: with the home rule placed before the catch-all, `/` became `/sites/anime/sites/anime` and
   rendered the 404. The frozen order (routes.md 1) puts the catch-all first, then the home, the root files and the
   pretty URLs written on the prefixed path. Unit tests simulate the chaining with Next's own functions.
2. **The layout guard works with layout-level params.** `generateStaticParams` and `dynamicParams = false` in
   `sites/[site]/layout.tsx` cover the child pages (the home renders with no params function of its own); a direct
   `/sites/anime`, `/sites/kpop`, `/sites/hub` or `/sites/anime/robots.txt` is a 404 on every build.
3. **K-pop leaks found and closed in the spike.**
   - An unmatched path rendered the root 404 with the root layout's kpop metadata: fixed by
     `app/sites/[site]/[...rest]/page.tsx` (notFound) and the site's own `not-found.tsx`, so the kpop
     `(site)/not-found.tsx` (popular K-pop groups) is never reached on anime or hub.
   - The root layout's description, keywords, authors, Open Graph, Twitter, icons, manifest and the Pinterest tag
     verifying kpopquiz.org reached every anime and hub page: the site layout resets them (`null`; the Pinterest
     tag needs an empty list, `other: {}` does not remove it). B1 removes the need when the root layout reads the
     registry.
   - The 404 title read "OtakuQuiz | KpopQuiz" (the root template wraps a layout's own default title): the site
     layout uses `title: { absolute, template }`.
4. **`isKnownRoute` cannot itself become site-aware.** The build guard (`check-route-allowlist.mts`, ratchet-locked)
   walks every page file of the repo on every build: a site-aware `isKnownRoute` would fail the anime and hub
   builds on the kpop pages they compile. It stays the kpop predicate plus `/sites/`; the site-aware question is
   `isKnownRouteFor`, which the middleware does not even need (it passes every public non-kpop path to the rewrites).
5. **Middleware on non-kpop builds.** One early return: `'pass'` for every public path (so the kpop Verse gate,
   the legacy `/blind-test` and `/create-preview` redirects, the name-all 410s and the kpop unknown-route answer never
   run there); the protected paths keep today's session branch. Seen in dev: anime `/settings` gives 307 to
   `/login?returnTo=%2Fsettings`, `/verse` and `/blind-test/x` give 404.
6. **Offline.** The spike pages read nothing, so they cannot fail offline. kpop pages are still compiled into the
   anime and hub builds but never reached (the rewrites send every public path under `/sites`); how they prerender
   offline in a production build is measured by the gate's `spike-build-anime` and `spike-build-hub` steps (this lane
   never runs `next build`); the kpop build is known to pass offline (Phase 0, 163 static pages). kpop `/bts-quiz`
   is a 500 offline in dev: `getGroupBySlug` throws on a database error (the ISR fail-closed rule), unchanged kpop
   behaviour.
7. **Dev server hygiene.** A dev server restarted on the same `.next` after a config change served stale routing
   (every rewrite but the home lost) until `.next` was removed. Every restart in this lane now starts from a clean
   `.next`.

## Decisions (frozen here, no document fixed them)

1. `isKnownRoute` stays the kpop predicate (plus `/sites/`); `isKnownRouteFor(site, ...)` is the site-aware one
   (finding 4).
2. Rewrite order and `CATCH_ALL_PATTERN` as in routes.md 1 (finding 1). Dotted paths are public files except under
   `/sites`.
3. Per-site robots.txt, sitemap.xml and llms.txt are route handlers under `app/sites/[site]/`, reached by rewrite;
   the kpop root files stay untouched. Replaces COLLISION-MAP row 13's dispatch inside the kpop files.
4. Every anime and hub 404 goes through `[...rest]` and the site's `not-found.tsx` (finding 3).
5. Brand assets of anime and hub live in `public/brand/<site>/` (never `public/sites/`, which would shadow the
   internal prefix). IndexNow key files of every site sit side by side in `public/`.
6. Pretty URL internals: `/{series}-openings-quiz` to `blindtest/series-{series}`, `/which-{series}-character-are-you`
   to `which-character/{series}`; the internal path also answers and carries the canonical of the pretty one.
7. This or that has no route on anime, as on kpop (a bonus inside results and hubs).
8. Anime features off where BACKLOG's anime route map has no route: leaderboards, ranked, news, articles, data
   pages, true or false, daily blind test (a CR adds the route and the key together).
9. Editorial caps: kpop `quizDailyCap` 0 (the kpop publisher has no quiz kind today), anime 40 a day (top of the G0
   range 25 to 40, "default, pending"), anime weekly limit 2 per series (BACKLOG B5), hub 0.
10. kpop `googleClientIdEnv` is null (Google through the Supabase OAuth redirect, untouched); kpop `signOutModes` is
    `['global']` (today's single button); anime and hub offer both scopes.
11. `passport.probeOrder` is `[]` on every site (the P2 hook is inert and read by nothing).
12. `SiteConfig` keeps the exact 5.1 field list; the placeholder list lives in `PLACEHOLDERS`, outside the shape.
13. Two disagreeing site env values throw at module load (a build must fail rather than serve the wrong site); a
    non-kpop build inlines `NEXT_PUBLIC_SITE_ID` through next.config `env`.
14. Non-kpop session paths in the middleware: `/login`, `/onboarding`, `/settings`, `/admin` and below (a subset of
    kpop's `needsAuth`, so today's protected branch serves them).
15. Per-site, per-lane copy files: `apps/quiz/src/copy/<site>/<lane>.ts` (details in copy-keys.md, slice 2).
16. Theme token names are the names a0.css really declares (`card-fill`, not "card"; `on-ok` already exists; there
    is no focus token): tokens.md (slice 2) freezes that list, BACKLOG's shorthand list maps onto it.
