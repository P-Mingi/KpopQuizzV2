## Blockers

1. apps/quiz/src/lib/passport/signout.ts:28 (used by apps/quiz/src/lib/passport/deletion/account.ts:128-132)
   - Why: `await client.auth.signOut({ scope })` ignores the result. supabase-js (auth-js 2.100.1, GoTrueClient._signOut) does not throw
     on an API or network failure: it returns `{ error }` and keeps the session. So `signOut` reports 'global' while every refresh token
     of the member stays valid, and /api/passport/delete answers 200 with sessions still alive on anime and hub (the comment at
     account.ts:131 is wrong: refresh tokens do not expire by themselves). The test at signout.test.ts only covers a throwing mock.
   - Smallest fix: `const r = await client.auth.signOut({ scope }); if (r && typeof r === 'object' && 'error' in r && r.error) throw r.error;`
     and in handleDelete do not swallow it: log `signout_failed` and answer 500 `server` (the request is idempotent, a retry refreshes it),
     or fall back to the service role `auth.admin.signOut(accessToken, 'global')`.

2. docs/pending-migrations/multisite/016-passport-deletion.rollback.sql:30
   - Why: the guard keeps only real `passport` runs (`counts ? 'mission_u_d_installed'`). A real leave (`kind = 'leave_world'`,
     `dry_run = false`, written by every POST /api/passport/leave) is just as destructive, but the rollback drops its log row silently:
     the rollback can lose the audit of real deletions, against its own stated rule.
   - Smallest fix: `... where dry_run = false and outcome = 'ok' and (kind = 'leave_world' or counts ? 'mission_u_d_installed')`.
