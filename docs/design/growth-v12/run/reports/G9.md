### Where editorial content lives

- Debates: `community_debates` (v11-p8-community.sql), written by the same insert as a fan debate.
- Threads and blogs: a new table `editorial_posts`. The existing thread and blog stores are Verse tables, shown
  only while the Verse is public and the space is live (decision 27), so an editorial thread there would be
  invisible today. Post URLs: `/community/thread/e<id>`, `/community/blog/e<id>` (noindex like all of /community).
- Replies and hearts on them use `community_replies` and `community_likes` with a new target type `editorial`
  (the SQL widens the two CHECKs; skipped with a notice when v11-p8-community.sql is not applied).
- Marked editorial: the author is a row of `editorial_accounts`, and `editorial_drafts.published_ref` points at
  the published row.

### Publisher

One item per run, the oldest due first. Rules in `rules.ts`: approved only, `reviewed_by` set and still an admin
(`ADMIN_USER_IDS`), `scheduled_at` reached, at most 3 per UTC day, never the account of the last published item,
active account only. The table also refuses an approved or published row without a reviewer (CHECK). A run claims
the draft before writing, so two overlapping runs cannot post twice; a failed write gives the draft back.
The publisher has two writes (`insertDebate`, `insertPost`) and calls no fan route: no XP, badge, streak, activity
event, notification or ticker line.

Strict reading of "never two in a row": if the only due drafts belong to the account that published last, nothing
is published until another account has. The admin page says so in its header.

### Additions to the SYSTEM.md 5.6 column list

`editorial_drafts` has the listed columns plus `debate_days`, `template_key` (one draft per template run),
`published_at` (the 3 a day rule), `created_at`, `updated_at`.

## 9. Owner decisions

1. Accounts: create 3 to 5 accounts yourself, then fill `v12-g9-editorial-accounts.sql` (it stops with an error
   until every placeholder is a real user id). Apply `v12-g9-editorial.sql` first.
2. Verse option: editorial threads and blogs could instead live in the Verse tables if the spaces were made
   public for them. Built: a separate `editorial_posts` table, so nothing depends on opening the Verse. Say so if
   you prefer the Verse route.
3. "Never two in a row" is strict (section 1). The softer reading (skip the rule when only one account has
   something due) is a one line change in `rules.ts`.
4. Retiring an account (`active = false`) removes its badge and its exclusions everywhere except on the posts it
   already published in `editorial_posts`, which keep the Team badge. Its past debates would show it as a fan.
5. Follow on a team post is kept, as the prototype shows it.
