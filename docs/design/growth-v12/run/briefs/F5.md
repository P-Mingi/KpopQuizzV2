# F5: Team badge and exclusions everywhere an editorial account appears (owner decision, 2026-10-03)

The 9 seed accounts become editorial accounts (`docs/pending-migrations/v12-g9-editorial-accounts.sql`, file 19). They
authored 155 published quizzes and have plays and XP. The owner's rules:
1. Everywhere an editorial account is named, it carries the Team badge (A1's `PersonName isTeam`, `TeamTag`,
   `UxAvatar team`) and shows NO level and NO XP.
2. They are left out of the leaderboards (incl. Ranked), the fandom war and the results rank "#N of M players".
   Stored play counters stay as they are: no recompute, no write.
3. Everything stays behind the v12 flag: with `NEXT_PUBLIC_UX_V12` off, every page, query, response and cache key is
   byte for byte today's, and no extra read happens. Team ids come only from `getTeamIds()` / `getTeamMap()` /
   `isEditorialUser()` in `src/lib/editorial/accounts.ts` and `teamIdsToExclude()` in `src/lib/db/queries/profiles.ts`
   (they read nothing and answer "nobody" with the flag off or before the SQL is applied).
4. SQL that must exclude them (fandom war `get_fandom_war_map`, the quiz rank function behind the results rank line)
   is written as a new file `docs/pending-migrations/v12-f5-<topic>.sql`, never applied, and it must not change the
   flag-off behaviour: add a parameter `p_exclude_team boolean DEFAULT false` (or a new function name), and only the
   v12 code passes true. Existing calls keep their exact signature and result. Read the current definition with the
   Read tool (the repo hook blocks shell commands naming the Supabase migrations folder; R1's applied files are in
   `docs/pending-migrations/` too). The app fails soft to today's call while the new SQL is not applied.
