SYSTEM.md 3 and the themed playlists of 4; V12 prompt 5.3.

- Ingestion: `apps/quiz/scripts/ingest-blindtest-songs.mts` gains `--dry-run --sql-out <file>`; it reads with the
  anon key and you run it only as `env -u SUPABASE_SERVICE_ROLE_KEY ... --dry-run`. It writes only with an explicit
  `--apply`, which this run never uses. (The repo hook blocks `_*.mts`, `check-*.mts`, `test-*.mts`: this file is
  not one of them. If the hook refuses the edit, stop and tell ORCH.)
- SQL files (idempotent, `insert ... on conflict do nothing`, header: what, why, rows, verify, undo, apply order),
  each with a dry-run report in `docs/growth/catalogue/`: groups RESCENE and NCT WISH (every fact from two sources,
  cited); songs for Hearts2Hearts, KickFlip, RESCENE, NCT WISH up to 10 clean songs each; 2026 releases of existing
  groups; sourced title tracks for the new songs and the hits playlists; the `language` `ko` / `korean` proposal in
  its own file after checking every reader; KPop Demon Hunters songs: fictional acts get their own non-active
  status, TWICE soundtrack songs keep their group and are listed by id.
- Before the KPDH file can be approved: grep every `from('songs')` reader (site, crons, ranked, daily, search,
  stats) on `origin/main` AND on `feat/v12` and prove the new status is excluded everywhere; if `main` would include
  it, the KPDH rows go in their own file marked "apply only after feat/v12 is merged".
- `generate`: year ranges, generation + gender, curated id lists (`lib/blind-test-curated.ts`, one public source per
  song for `tiktok-viral`), the KPDH playlist. Each of v11 decision 33's nine modes plays as named when the data
  allows; list the rest. New themed modes (`kpop-hits-2026`, `kpop-hits-2025`, `5th-gen`, `tiktok-viral`,
  `kpop-demon-hunters`) join `STATIC_MODES` only when `isUxV12()` (A1 ships `lib/ux-v12.ts`; until it is merged use
  the same two env tests inline and switch after). A themed playlist with fewer than 10 playable songs stays hidden.
- Web research is allowed for sourcing (official sites, labels, reference wikis, Deezer public API reads). No
  photo scraping.

Done when: SQL files and dry-run reports written, generate unit tests green (each filter, the excluded status,
the hidden-under-10 rule), the reader grep proof in your report, flag-off diff of `/api/blind-test/generate` answers
