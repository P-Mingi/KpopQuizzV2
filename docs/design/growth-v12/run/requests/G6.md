# G6 requests

## R1 (ORCH): the pretty URL rewrite in `apps/quiz/next.config.ts`

What: a `rewrites()` block, flag on at build only. Exact lines (also as a patch that applies on `feat/v12` at
`21c7e58`: `run/reports/G6/next-config.patch`), placed between `redirects()` and `images`:

```ts
  async rewrites() {
    const on = (v: string | undefined): boolean => v === '1' || v === 'true';
    if (!on(process.env.NEXT_PUBLIC_UX_V1) || !on(process.env.NEXT_PUBLIC_UX_V12)) return [];
    return [
      {
        source: '/:group(bts|blackpink|stray-kids|twice|aespa|newjeans|seventeen|exo|g-i-dle|ive|le-sserafim|red-velvet|ateez|enhypen|txt|itzy|shinee)-name-all-members',
        destination: '/name-all/:group?via=pretty',
      },
    ];
  },
```

If another agent already asked for a `rewrites()` block, the one object above is the only G6 line: add it to the
same returned array.

Why: `/name-all/[group]` is the internal route; the public, indexable URL is `/<group>-name-all-members`
(SYSTEM.md 5.1). The `?via=pretty` marker is how the page tells the two apart: with it the page is
`index, follow`, without it (a direct hit on `/name-all/<group>`) it is `noindex, follow`. Both carry the same
canonical, the pretty URL. Do not drop the query from the destination.

The exact group list (17 groups, 109 members, each list checked against the database, `run/reports/G6/roster-check.txt`):

```
bts blackpink stray-kids twice aespa newjeans seventeen exo g-i-dle ive le-sserafim red-velvet ateez enhypen txt itzy shinee
```

The same list is `NAME_ALL_GROUPS` in `apps/quiz/src/lib/name-all/spellings.ts`. The page answers 404 for any
other group, so a slug in the rewrite and not in that list is a 404, never a broken page.

Redirect exceptions: none needed. Measured on the base: no entry of `redirects()` matches `/<group>-name-all-members`
or `/name-all/<group>` (the REFONTE block only covers `/games/name-all/*`, which keeps its 308 to `/quizzes`).
With a flag off both URLs get the middleware's 301 to `/`, before and after this change.

`route-allowlist.ts`: nothing to add. `/name-all/` and the `-name-all-members` suffix rule are already there.

Measured with the patch in the working tree (never committed by G6), dev server, three flag states:
`run/reports/G6/flag-off/`.
