# Requests from A1 Foundation v12

## R1 (to ORCH). The stylesheet route serves the v12 rules only with the v12 flag

- File: `apps/quiz/src/app/api/ux-v1/a0/styles/route.ts`. It is in nobody's globs in `run/OWNERSHIP.json` (A1 owns
  `lib/ux-v1/a0/**` and `styles/ux-v1/a0.css`, not `app/api/ux-v1/a0/**`), so the guard would reject it from A1.
- What: apply `docs/design/growth-v12/run/reports/A1/styles-route.patch` (`git apply` from the repo root). The route
  body becomes one call, `buildUxStylesheet({ v12: isUxV12() })` from `lib/ux-v1/a0/stylesheet.ts` (already on the A1
  branch with its unit tests). No other change: same `force-static`, same 404 when `NEXT_PUBLIC_UX_V1` is off, same
  cache header.
- Why, 1: the shared v12 rules live in one marked block at the end of `styles/ux-v1/a0.css` (the only stylesheet A1
  owns). With `NEXT_PUBLIC_UX_V12` unset the builder cuts that block before minifying, so a v11-only build serves the
  same stylesheet bytes as before v12 (unit test: equal to the old route algorithm on an `a0.css` without the block).
  Without the patch a v11-only build serves 12,861 more bytes (the minified v12 block; 180,626 instead of 167,765 on dev) of inert v12 rules (no v11 class matches them, the HTML is the
  same), which is not "byte for byte".
- Why, 2: with both flags on the builder also serves every `apps/quiz/src/styles/ux-v12/<id>.css` (name order, after
  the v11 sheets). This is how the G agents' page sheets (`g3.css` ... `g9.css`) go live, as COMMON.md says. Without
  the patch those files are never served.
- State: every v12 view (any `styles/ux-v12/<id>.css`), and the `stylesheet` test of `e2e/ux-v12/a1.spec.ts`, which
  fails in the v11-only state until the patch is in.
- Checked by A1 with the patch applied locally (not committed): `a1.spec.ts` green in the three flag states, see
  `run/reports/A1.md`.
