# Requests from G5 (Personality engine)

Everything here is in a file G5 does not own. Paths are under `apps/quiz/`.

## R1 (ORCH): `next.config.ts`, the rewrite and the redirect exception for Which member are you

Why: the page lives at the internal route `app/(site)/personality/[group]` and is public only at
`/which-<group>-member-are-you`. Today `next.config.ts` 301s every `/which-:group-member-are-you` to the group hub
(REFONTE P1). Redirects run before rewrites, so the listed groups must leave that redirect, flag on only.

The exact patch G5 ran every check with (working tree only, never committed) is
`docs/design/growth-v12/run/reports/G5/next-config.patch`. Its three parts:

1. Near the top of the file (the flag, if no other request added it already, and the group list):

```ts
const on = (v: string | undefined): boolean => v === '1' || v === 'true';
const UX_V12_ON = on(process.env.NEXT_PUBLIC_UX_V1) && on(process.env.NEXT_PUBLIC_UX_V12);

const WMA_GROUPS = [
  'aespa', 'ateez', 'blackpink', 'bts', 'enhypen', 'g-i-dle', 'itzy', 'ive',
  'le-sserafim', 'newjeans', 'nmixx', 'seventeen', 'stray-kids', 'twice', 'txt',
];
const WMA = WMA_GROUPS.join('|');
```

2. In `refonteRedirects`, the line
   `{ source: '/which-:group-member-are-you', destination: '/:group-quiz', permanent: true },` becomes:

```ts
{
  source: UX_V12_ON ? `/which-:group((?!(?:${WMA})-member-are-you)[^/]+?)-member-are-you` : '/which-:group-member-are-you',
  destination: '/:group-quiz',
  permanent: true,
},
```

3. A `rewrites()` entry (merge it with G6's if `rewrites()` already exists):

```ts
async rewrites() {
  if (!UX_V12_ON) return [];
  return [
    { source: `/which-:group(${WMA})-member-are-you`, destination: '/personality/:group' },
  ];
},
```

The exact group list (15 slugs, the groups with an active profile set in `personality_profiles`, read on
2026-10-02): `aespa`, `ateez`, `blackpink`, `bts`, `enhypen`, `g-i-dle`, `itzy`, `ive`, `le-sserafim`, `newjeans`,
`nmixx`, `seventeen`, `stray-kids`, `twice`, `txt`.

Keep as they are (G5 relies on them):
- `{ source: '/personality', ... }`, `{ source: '/personality/:group', ... }` and
  `{ source: '/personality/:group/r/:member', ... }`: a direct hit on the internal route keeps its 301 to the hub,
  so each page has one indexable URL. A rewrite destination is not redirected, so the pretty URL still renders.
- `{ source: '/which-:group-member-are-you/r/:member', ... }`: the old result permalinks keep their 301.

Measured with the patch on `next dev` (flag on): the 15 pretty URLs answer 200; `/which-nope-member-are-you` and
`/which-illit-member-are-you` (a real group without a profile set) 308 to the hub; `/personality/stray-kids` 308;
with either flag off every one of them answers exactly as on the base (`run/reports/G5/flag-off/*.txt`).

`lib/route-allowlist.ts` needs nothing: `/personality/` and the `/which-...-member-are-you` suffix rule are already
flag-only routes there, and `/kpop-demon-hunters-quiz` ends with `-quiz`.

No cron, no env var, no `vercel.json` change.

## R2 (G3): sitemap, flag on only

Add to `src/app/sitemap.ts`, inside the `isUxV12()` branch only:

- `/kpop-demon-hunters-quiz` (one URL, always, when the flag is on).
- `/which-<slug>-member-are-you` for each slug returned by
  `import { getWmaGroupSlugs } from '@/lib/personality/data'` (`await getWmaGroupSlugs()`, never throws, returns `[]`
  when the read fails, so a database blip drops the entries instead of failing the sitemap). Path helper:
  `import { whichMemberPath } from '@/lib/personality/view'`.

Both are indexable (index, follow, canonical to themselves). `/personality/*` must never be listed.
Suggested `changeFrequency: 'monthly'`, `priority: 0.6`, no `lastModified` invented (the tables have no date).
