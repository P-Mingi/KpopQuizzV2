## R1. G1 (or ORCH assigns a G3 SQL glob): the count behind "N fans playing today" (blocks: the line, not the pages)

- What: one function, added to a pending SQL file (never applied without the owner's `go`):

```sql
-- "N fans playing today" on the blindtest landings: distinct players with a run started
-- during the current UTC day. One integer, no row, no id: safe for the anon key.
-- Test runs (localhost, previews) and bots never count.
CREATE OR REPLACE FUNCTION public.bt_fans_today()
RETURNS integer
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
  SELECT count(DISTINCT coalesce(player_id, anon_id))::integer
  FROM public.bt_runs
  WHERE is_test = false
    AND user_agent_class <> 'bot'
    AND created_at >= date_trunc('day', now() AT TIME ZONE 'utc') AT TIME ZONE 'utc';
$$;
REVOKE ALL ON FUNCTION public.bt_fans_today() FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.bt_fans_today() TO anon, authenticated, service_role;
-- verify: select public.bt_fans_today();                       -- an integer, 0 on a fresh table
--         select has_function_privilege('anon', 'public.bt_fans_today()', 'execute');  -- t
-- undo:   DROP FUNCTION IF EXISTS public.bt_fans_today();
```

- Why: SYSTEM.md 4 says the line comes only from `bt_runs`. The table has row level security and no policy
  (`v12-g1-bt-runs.sql`), so the anon key reads nothing, and `lib/supabase/server.ts` keeps the service role for admin
  routes. A definer function that returns one integer is the smallest door. `docs/pending-migrations/` is not in the
  G3 globs, so G3 could not write the file.
- State: flag on. Until the function exists `getFansToday()` (`apps/quiz/src/lib/growth/bt-data.ts`) gets an error and
  the eyebrow is not rendered at all (measured on dev today: no eyebrow on the four landings). After the apply it
  appears as soon as the count is above zero, with no code change.
- File: a new `docs/pending-migrations/v12-g1-bt-fans-today.sql` (or the tail of `v12-g1-bt-runs.sql` if it is not
  applied yet).
