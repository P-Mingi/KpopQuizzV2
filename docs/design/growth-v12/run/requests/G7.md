# G7 requests

## R1 (ORCH): the nightly cron in `apps/quiz/vercel.json`

What: one entry in the `crons` array.

```json
{ "path": "/api/cron/fans-picked", "schedule": "40 3 * * *" }
```

Why: the Fans picked ranking (Bradley-Terry + weekly movement) is recomputed once a night from `duel_votes`.
03:40 UTC sits between `prune-activity` (03:30) and `notification-prune` (04:00); it reads about 5,000 vote rows
today and takes a few seconds (`maxDuration` 60 in the route).

Safe to add at any time: the route answers 404 unless `isUxV12()`, 401 without `CRON_SECRET`, and
`{ ok: false, reason: "not_applied" }` (HTTP 200, nothing read or written) until
`docs/pending-migrations/v12-g7-this-or-that.sql` is applied.

File: `apps/quiz/vercel.json` (ORCH's). If `lib/vercel-config.test.ts` counts the crons, its expected number moves
by one.

## R2 (G8): the "<Fandom> picked" section on the group hub

Nothing to change in a shared file. What G8 needs from G7:

- Data, server side: `import { getFansPicked } from '@/lib/duel/server'`, then `await getFansPicked(group.slug)`.
  It never throws. Same data over HTTP: `GET /api/duel/fans-picked?group=<slug>`. Shape:
  `FansPickedResponse` in `apps/quiz/src/lib/duel/types.ts`.
- Render the section only when `ranked` is true. `songs` is the top 10 (rank, title, year or null, Deezer cover
  or null, votes, movement or null, isNew). `votes` is the group's counted vote total. Show the movement only
  when `hasMovement` is true.
- Give the section the id `fans-picked`: the bonus card's last screen links to `/<slug>-quiz#fans-picked`
  ("See what ARMY picked"), only when the group is ranked.
- "Vote" opens the pairs: mount `<ThisOrThatBonus groupSlug groupName />` from
  `@/components/this-or-that/bonus` (client component, styles in `styles/ux-v12/g7.css`, already served with the
  v12 sheets). It renders nothing when the server has no pair for the visitor. If the hub needs another kicker
  or heading than "Bonus · This or that", ask G7 for a prop rather than copying the component.

## R3 (ORCH, optional env): `DUEL_SIGNING_SECRET`

Not required. The pair tokens and the voter hash use a key derived from `SUPABASE_SERVICE_ROLE_KEY` (HMAC with a
fixed label; the service key itself is never used as the key and never leaves the server). Setting
`DUEL_SIGNING_SECRET` (16 characters or more) in Vercel gives the feature its own key. Changing the key later
changes every voter hash, so a fan could vote once more on a pair that day; nothing else breaks.
