# P1 (Home) requests to A0

1. Focus the page H1 on client navigation (DESIGN-SPEC 16.5: "On client navigation: update
   document.title, focus the page H1 (tabindex -1, no focus ring)"). Today the shell focuses
   nothing on a route change (`ux-client-shell.tsx` gives `main#main` tabIndex -1 but no route
   hook moves focus). The home H1 already carries `tabIndex={-1}` (`components/home/ux-v1/home-header.tsx`)
   so the shell only has to call `document.querySelector('.ux-main h1')?.focus({ preventScroll: true })`
   after a client navigation. Why: keyboard and screen-reader users land at the top of the new
   page instead of on the link they clicked. Prototype state: any `go('...')` view change.

3. Keep the `/search` link in the server HTML (SEO link parity, ORCH blocker on P1). The live
   chrome renders `<a href="/search">` on every page; the v11 nav's search control is a `<button>`,
   so `/search` disappears from the server HTML of `/` and `/pt` (and every page with the shell).
   Proposed: render the control as `<a href="/search" aria-label="Search">` whose click handler opens
   the overlay (`preventDefault`), keeping "/" and the overlay as they are. Found by P1's full link
   parity check (`v11/reports/P1/proofs/link-parity.txt`); it is the only live-chrome href missing.

   (Turbopack, root inferred = main checkout) serves the layout with a
   `<link rel="preload">` to a `src_lib_supabase_client_ts_<hash>` chunk that 404s. It did not
   break the home once `.next` was cleared, but the sign-in sheet imports the Supabase client on
   click, so it may fail on a worktree dev server. Not reproduced on `next build` + `next start`.
