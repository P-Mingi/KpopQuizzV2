# P5 requests (create funnel)

Append-only. Each item: what, why, which prototype state, who.

## 1. ORCH: one copy of the funnel rules (create-funnel.tsx and question-list-editor.tsx are unowned)

- What: make `apps/quiz/src/components/create/create-funnel.tsx` import `toApiQuestion`, `uploadDeferredImages`,
  `publishPayload` / `publishQuiz`, `emptyState`, `questionHasContent`, `draftToState` and `stateToDraft` from
  `apps/quiz/src/lib/ux-v1/p5/funnel.ts`, and `apps/quiz/src/components/quiz/question-list-editor.tsx` import the
  list operations (`patchAt`, `moveItem`, `duplicateItem`, `removeItem`, `addItem`) from
  `apps/quiz/src/lib/ux-v1/p5/questions.ts` (or move both modules to a neutral `lib/create/`). Pure refactor,
  flag-off output unchanged.
- Why: the brief says "re-skin, never rewrite their state, validation or save calls", and both files are in nobody's
  OWNERSHIP globs, so the v11 view runs verbatim copies. `lib/ux-v1/p5/funnel.test.ts` and `questions.test.ts` lift
  the legacy code out of the two files at test time and prove the same state, the same gate messages and the same
  requests in the same order (cover upload, deferred image uploads, POST /api/quiz/create with the same body, keys
  in the same order); they fail the moment either side changes, but one copy is better.
- Also (flag-off behaviour, owner call): the legacy autosave can re-save a draft that publish has just cleared when
  the publish answers inside the 500 ms autosave window (the resume-after-sign-in path flips `hydrated` right before
  publishing), so the next visit to /create shows the published quiz again as a draft. The v11 hook guards it with
  `if (!hydrated || published) return;` in the autosave effect; the legacy can take the same line.
- States: create-1, create-2, create-3, signin.

## 2. A0: sign-in sheet title line-height

- What: `.ux-sh-h h2, .ux-sh-h h3` is 18px / 1.4 (25.2px); the prototype's `#signin .sh-h h3` is 18px / 1.6
  (28.8px), so the sheet is 3.6px shorter than the reference.
- Why: shared component (`components/ux-v1/sheet.tsx`, `styles/ux-v1/a0.css`). `e2e/ux-v1/p5.spec.ts` skips that one
  property on the signin state with a pointer to this request.
- State: signin (1440 and 390, light and dark); also every other sheet (share, header-sheet, editor).

## 3. A0: a preview mode for UxQuizCard

- What: a prop on `UxQuizCard` (for example `preview` or `href={null}`) that renders the same card without the link
  and accepts a cover that is a data URL (a plain `<img>`; `next/image` refuses it and `isConfiguredImageHost`
  rejects it today).
- Why: step 3 shows "How it will look" with the draft, whose cover is a compressed data URL until publish and which
  has no `/q/<slug>` yet. P5 renders it with `DraftCard` (`components/create/ux-v1/publish.tsx`): A0's classes and
  `LevelBars` / `levelOf`, no copied logic. With a preview mode P5 deletes `DraftCard`.
- State: create-3, signin (`.qcard` landmark of styles.json: green).

## 4. A0 (info, owner call): the sign-in callback origin on previews

- What: the sheet builds `redirectTo` / `emailRedirectTo` from `NEXT_PUBLIC_SITE_URL` (as `/login` does); the legacy
  funnel used `window.location.origin`. Same on production. On a Vercel preview whose `NEXT_PUBLIC_SITE_URL` is the
  production URL, the round trip lands on production, where the draft (localStorage of the preview origin) is not.
- Why: the owner will test the create flow on a preview (data-safety rule 7). Auth logic is under rule 4, so this is
  only a note.
- State: signin.

## 5. P8 (through ORCH): open the composer in challenge mode from the create done state

- What: "Post a challenge" on the done state links to `/community?compose=challenge&quiz=<slug>`. Please open the
  community composer in challenge mode for that quiz when these parameters are present (prototype:
  `openEditor('challenge')` after publishing; WIRING-MAP 6 "Done state ... Post a challenge").
- Why: `/community` and its composer are P8's. Without the parameters handled, the link lands on the feed.
- State: create done state (no reference capture; prototype `#pub-done`).
