# P4 requests (quiz page, game, results)

Append-only. Each item: what, why, which prototype state, who.

## 1. ORCH: one copy of the quiz rules (quiz-player.tsx is unowned)

- What: make `apps/quiz/src/components/quiz/quiz-player.tsx` import `getEffectiveOptions`, `getCorrectIndex`,
  `isAnswerCorrect` and the reducer from `apps/quiz/src/lib/ux-v1/p4/engine.ts` (or move that module to a
  neutral `lib/quiz/run-engine.ts` that both import) instead of its inline copies. Pure refactor, flag-off
  output unchanged.
- Why: the brief says "never fork the scoring". quiz-player.tsx is in nobody's OWNERSHIP globs, so P4 could
  not edit it; the v11 game therefore runs a verbatim copy. `lib/ux-v1/p4/engine.test.ts` lifts the legacy
  rules and reducer out of quiz-player.tsx at test time and proves the two give the same state on every case
  (classic, true/false with and without options, clues, timeouts, ignored actions) and the same save payload
  keys. That test fails the moment either side changes, but one copy is better.
- States: play, play-answered, end, end-guest.

## 2. ORCH: a short challenge URL (optional)

- What: a `/c/<code>` route that 301s to `/q/<slug>?c=<id>.<sig>` (the prototype shows
  `kpopquiz.org/c/7KQ2PX`), plus its `lib/route-allowlist.ts` entry.
- Why: new route outside P4's globs and the allowlist is ORCH's. Today the challenge link is the signed quiz
  page URL, which works and keeps the canonical page (no new indexable URL).
- State: share (challenge link block).

## 3. A0: `useUxMe()` can differ between SSR and the first client render

- What: have `useUxMe()` (or `lib/auth/use-me.ts useMe()`) return `null` until mounted.
- Why: `useMe()` seeds its state from a module cache, which the shell's islands have usually filled by the
  time a page island hydrates; an SSR-rendered island that shows guest-only text ("No account needed.")
  then hydrates with different markup (React hydration error). P4 guards with `useIsClient()` in its own
  islands; any other page island rendering auth-dependent text on the server hits the same trap.
- State: quiz (guest timer line).

## 4. P1 (home "Continue playing"): the store to read

- What: read saved runs with `readContinueRuns()` from `@/lib/ux-v1/p4/continue` (newest first, 14-day
  expiry, max 6) and link each row to `resumeHref(slug)` (`/q/<slug>?resume=1`). Each entry has `title`,
  `groupName`, `groupSlug`, `quizType`, `difficulty`, `total`, `answered` (progress = answered / total).
- Why: DESIGN-SPEC 16.7 "quit ... saves the run to Continue"; the quiz game writes the entry when a player
  leaves after answering, and resumes it at the saved question.
- State: home (Continue playing), play (quit confirm).

  on the Copy link button would match.
- Why: shared component (components/ux-v1/share-sheet.tsx, styles/ux-v1/a0.css), A0's files.
- State: share (390 light / dark).
