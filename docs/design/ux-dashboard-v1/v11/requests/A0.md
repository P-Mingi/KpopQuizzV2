### P1.md 1: focus the page H1 on client navigation

- Fixed in f11ec96 + f068e25 (`components/layout/ux-v1/ux-chrome-gate.tsx`, `UxRouteFocus`, mounted by the
  shell for every v11 page). It existed with a single 60 ms timer, which missed the H1 of routes with a

- Proof: `shell.spec` "client navigation" (1440 nav links, 390 tab bar, a quiz behind `loading.tsx`, Enter on

### P2.md 3: `Segmented` and `UxDropdown` with link options

- Shipped in be317bb. `Segmented({ options: { value, label, href? }[], value, onChange?, onNavigate?, label })`:
  when every option has an `href` it renders `<nav class="ux-seg" aria-label>` of real links (next/link,
  `prefetch={false}`, `scroll={false}`), `aria-current="page"` on the pick, the same pill as the pressed

  a right-aligned `<small class="ux-num">`. Both: a plain click navigates softly, or calls
  `onNavigate(href, value)` instead (pass P2's `go`); modified clicks keep the browser's behaviour; clicking
  the current pick does nothing. The menu items render while the menu is open (as P2's own menu does today).
- Proof: `kit.spec` "link options" on the kit's link versions (pick in `?kitsort` / `?kittype`).
