# P2 requests (quizzes browse)

Append-only. Each item: what, why, which prototype state, who.

## 1. A0: the shell's search control must be a real `<a href="/search">` (link-set rule)

- What: render the top-bar search control (`components/layout/ux-v1/ux-nav-actions.tsx`, the `.ux-sbtn` button) as
  `<a href="/search" aria-label="Search" ...>` whose plain click opens the overlay (`preventDefault`), instead of
  a `<button>`. Modified clicks and no-JS visitors then reach the live `/search` page.
- Why: COMMON.md done-when 5 (link set). The live top bar serves `<a href="/search">` on every page
  (`components/layout/mobile-top-bar.tsx`); the v11
  shell serves no `/search` link, so every flag-on page loses it. Measured on P2's URLs (flag off :3042 vs flag
  on :3032): `/quizzes/popular-today`, `/quizzes/popular-this-week`, `/quizzes/popular-this-month` and
  `/pt/quizzes` lose exactly one link each, `/search`, and nothing else (every other nav and footer link is
  kept). P2's own /quizzes views carry a `/search` link in their browse links, so they lose nothing, but pages
  P2 only wraps (the popular windows, unchanged content) cannot be fixed from P2's files. Same finding as P4's
  report 3.5 ("the only flag-off href missing flag on is /search").
- State: every state with the top bar (quizzes, home, ...).

## 2. A0: quiz card body line heights (card height 2.6px short at 1440, row 1.4px tall at 390)

- What: in `styles/ux-v1/a0.css`, give `.ux-qg` and `.ux-qf` `line-height: 1.6` (20.8px at 13px, the
  prototype's inherited value; today 1.5 = 19.5px), and in the phone stack
  (`.ux-qgrid.ux-qgrid-stack .ux-qt`) `margin-top: 0` (the prototype's `.qgrid.stack h3{margin-top:0}`).
- Why: measured on the first card of state `quizzes` (prototype vs /quizzes, same title length):
  1440: `.qcard` 262 x 329.78 in the prototype, `.ux-qcard` 262 x 327.19 (eyebrow 20.8 vs 19.5, footer 34.8 vs
  33.5); 390 stack row: 118.78 vs 120.19 (title 4px lower, eyebrow and footer 1.3px shorter each). The 1440
  height is outside the 2px landmark rule, so P2's spec compares `.qcard` by width only (as A0's kit spec does)
  until this lands. Every page with UxQuizCard (home, groups, hubs) has the same offset.
- State: quizzes (and home, hub-* wherever quiz cards show).

## 3. A0: `Segmented` and `UxDropdown` with link options

- What: an optional `href` per option. `Segmented`: when every option has one, render
  `<nav aria-label>` with `<a aria-current="page">` children (same pill look as `button[aria-pressed="true"]`).
  `UxDropdown`: menu items as `<a role="menuitemradio" aria-checked>` with an optional count (`<small>`).
- Why: the P2 brief requires every sort and filter to be a real `<a href>` (crawlable, works before hydration,
  opens in a new tab). A0's two components take buttons only, so P2 composes the same look from A0's classes
  (`.ux-seg` + a `.p2-sort > a` rule that repeats `.ux-seg > button`, `UxPopover` + `.ux-dd` + `.ux-mi` links)
  in `components/quizzes/ux-v1/controls.tsx`. Once A0 ships link options, P2 swaps to them and drops the
  repeated rule (`styles/ux-v1/p2.css`, "sort (links)").
- State: quizzes (sort + Type / Level / Group), groups and hub filters later.

## 4. A0: `UxDropdown` option to keep the trigger label on /quizzes (the chips carry the pick)

- What: an optional prop on `UxDropdown` (for example `showValue={false}`) that keeps the trigger text at
  `label` when a value is picked, while the items keep `aria-checked` (and the value can stay in the trigger's
  accessible name through a visually hidden span, as P2's own trigger did before it moved to `UxDropdown`).
- Why: in the prototype's `#quizzes` view `ddPick` never renames the trigger (`b.firstChild.textContent` is
  only rewritten outside `#quizzes`); the pick shows as a removable chip. `UxDropdown` renders
  `Type: <b>True/false</b>` once a value is set. Measured on `/quizzes?type=tf&level=hard` against the
  prototype with the same two filters: 1440, Type 174.1 px wide (prototype 91.6), Level 137.3 (93.9), the
  controls move 126 px left; 390, the three triggers no longer fit one line and Group wraps, so the chips and
  the grid sit 52 px lower than in the prototype. The default state (no filter, the reference capture) is
  equal. P2 passes `value` to keep the radio state right and records this as its only filtered-state
  deviation (reports/P2.md, pixel pass).
- State: quizzes with a Type, Level or Group picked.
