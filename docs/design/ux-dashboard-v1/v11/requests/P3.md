  has no `<a href="/search">` at all (the nav search is a `<button>` that opens the overlay). The link-set diff of

## 2. Today's hub reads cache a failed Supabase read as "empty" (C3-002, hub side; to ORCH, shared files)

- What: every read of today's hub that the v11 hub reuses swallows the Supabase `error` (`data ?? []`,
  `count ?? 0`, `return []`), so `unstable_cache` stores the empty answer for its TTL (catalog or stats, up to an
  hour) and every hub render in that window, flag on AND flag off, drops the section. P3's `read()` only sees a
  throw or a timeout, so the v11 hub cannot fail closed on these.
- Seen live in fix loop 1 on the loaded database: the war map RPC failed once, `getFandomWarMap` cached `[]`, and
  every flag-on hub lost "#N in this week's fandom war" and its `/leaderboard#fandom-war` link (BLACKPINK, BTS,
  Cortis) while the flag-off server, whose entry was still good, kept it. Chungha lost the W8 answer "2 Chungha
  songs are playable in the kpopquiz.org blind test." the same way (`getGroupBlindtestInfo` cached `songs: 0`).
  Both came back after the dev cache was cleared (`v11/reports/P3.md`, fix loop 1).
- Reads: `getGroupNameAllGame`, `getGroupBlindtestInfo`, `getGroupMasteryAgg` (fan knowledge), `getGroupActiveComeback`,
  `getGroupMvPulse` (`lib/db/queries/group-hub.ts`); `getFandomWarMap`, `getActiveFansByGroup`
  (`lib/db/queries/community.ts`); `getGroupContentDate` (`group-freshness.ts`); `getRelatedQuizzes`
  (`related-quizzes.ts`); `getOverriddenFacts` (`lib/trivia/facts.ts`, behind `hasTriviaPage`: a failed read today
  also 404s the trivia page and hides its link for the catalog TTL). `getQuizzesByGroup` already throws.
- Why not P3: those files are shared with the flag-off site and are outside P3's paths.
- Fix, ready to apply: `v11/reports/P3/fail-closed-queries.patch` (39 added lines; `git apply --check` is clean on

  value, and `unstable_cache` never stores a throw. `getRelatedQuizzes` moves from `.single()` to `.maybeSingle()`

- Callers to check before applying (a throw now reaches them instead of an empty value): today's hub and trivia
  page (`group-quiz-page.tsx`, `group-trivia-page.tsx`, `[slug]/page.tsx`; their reads go through `safeFetch`, so
  they render today's fallback and simply stop caching it), `q/[slug]/page.tsx` (`hasTriviaPage`,

- With it applied, the v11 hub fails closed end to end with no P3 change: its `read()` already turns a throw into
  `READ_FAILED`, and `failClosed()` keeps the last good ISR page.
