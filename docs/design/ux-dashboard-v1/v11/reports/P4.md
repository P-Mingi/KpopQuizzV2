### Decisions and deviations (for ORCH / owner)

1. Breadcrumb stays "Home / {Group} Quiz / {title}" (its BreadcrumbList JSON-LD is locked); the prototype's
   "Quizzes / BTS / {short title}" would change it. One line, the title ellipsizes.
2. Crawlable content kept inside the prototype layout: the stats-block numbers moved to the meta line
   (plays, average), the hall-of-fame header (perfect scores, fastest) and one muted line in the About box
   (pass rate, likes, reactions, comments); the full question list is a native `<details>` under "In this
   quiz"; "Read more about {group}" links sit under the text cards (groups with articles only).
3. Hall of fame = today's board (best row per signed-in player, guest rows shown as "someone"), top 5,
   minus relaxed runs once the column is live. On popular quizzes the top 5 are often guests; showing
   signed-in players only is an owner call.
4. Relaxed runs: saved through the existing endpoint with the same keys and `time_taken_seconds: null`
   (so `quiz_time_stats` and "fastest" ignore them), then marked by the new route. Challenge runs always
   use the timer.
5. Challenge links are `/q/<slug>?c=<id>.<sig>` (canonical unchanged). The HMAC signature (server secret:
   `UX_P4_CHALLENGE_SECRET`, else derived from the service role key; never sent to a client) is what makes
   a `battles` row a challenge, because that table accepts public inserts (migration 073). A guest
   challenger shows as "your friend".
6. "Play again" replays the same quiz (prototype), not `/quizzes` (legacy).
7. Stamp words come from `getResultLabel()` (a perfect run is "올킬! PERFECT"; the prototype sample used
   "대박!"), trailing "!" dropped as in 14.4.
8. Touch devices show A-D chips and hide the Enter hint (16.7 "A-D on touch", 16.9 "key hints hidden on
   touch"); the 390 reference PNGs were captured without `(hover: none)` and show 1-4.
9. Hearts and replies on quiz comments: first left out (no store); fix loop 3 (section 11, X1-002)
   adds them on a pending store, hidden until it is applied (no dead controls). The level-up overlay and the streak-backup nudge are the
   EXISTS components. (The legacy Discord results line and Brag button were first left out; C2-003 put
   them back, section 9.)
10. The group's blindtest row reads the playlist list once an hour (`unstable_cache`); on a cold cache the
    page's 5 s fetch budget can fall back to the generic "K-pop blindtest" row for that hour (fail soft).

## 12. Fix loop 4 (S1: C2-008 cases fail on a `next start` build)

### 12.1 Root cause: environment, not the app (candidate a)

- The root layout renders `<Analytics />` (`@vercel/analytics` 2.0.1). In production it injects
  `<script src="/_vercel/insights/script.js">`; in development it loads
  `https://va.vercel-scripts.com/v1/script.debug.js` instead (`getScriptSrc` in the package).

  middleware, `isKnownRoute('/_vercel/insights/script.js')` is false, and the unknown-route rule answers
  `301 Location: /`. The browser follows it, gets the home page (`200 text/html`) and runs it as a
  classic script: `SyntaxError: Unexpected token '<'` at line 0, on every page. C2 saw the same on every
  page locally (`checks/backend/README.md`, environment notes).
- Proof, flag-on production preview on :3021 (read only), guest `/q/skz-true-or-false-only-real-stays-pass`,

  or fetch request is that script, redirected `301 -> /` and answered `200 text/html; charset=utf-8`;
  no app fetch answered HTML. Playwright's `pageerror` carries this error with an EMPTY stack and no url,
  which is why the failing assertion showed only the message.
- Red on :3021 before the change: both cases pass every functional check (results up, `data-standing="none"`,

### 12.2 Change (spec only, no app code)

`e2e/ux-v1/p4.spec.ts`: `recordUncaught(page)` keeps Playwright's `pageerror` as the asserted signal and,

test. Each ignored error is written to the test's annotations. A self-check at the end throws an error
from page code and requires it to be reported, so the filter cannot hide app errors. The comment above
