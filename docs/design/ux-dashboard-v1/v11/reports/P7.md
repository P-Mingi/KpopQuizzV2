## Engine API

All in `apps/quiz/src/lib/ranked/`. Numbers live in `constants.ts`.

| Module | What it does |
|---|---|
| `scoring.ts` | `speedBonus(ms)`: 100 under 2 s, then `round(100 x (10 - t) / 8)`, 0 at 10 s. `comboTenths(streak)`: x1.0 on the first right answer, +0.1 per right answer in a row, cap x2.0. `scoreRound`, `scoreRun` (quit run: missing rounds score 0), `maxRunPoints()` = 2,900. Integer-exact (tenths), round half up. |
| `tiers.ts` | `TIERS` (Bronze 0 / Silver 4,000 / Gold 6,500 / Platinum 8,500 / Diamond 10,500 / Master 12,000), `tierFor(score)` with III/II/I as integer-exact thirds (`3 x (s - lo) < range` = III, `< 2 x range` = II), `tierSteps()` (16 steps), `nextStep(score)` ("210 points to Platinum III"), `isPromotion`. |
| `season.ts` | `bestRuns` / `seasonScore` (best 5; equal points: the earlier run keeps its place, so a run must BEAT the 5th best), `scoreToBeat` ("Score over 1,420 to count"), `seasonAvgAnswerMs` (tie-break), `placement(n)` ("3 / 5 placed"), `applyRun(previous, run)` = the Season impact block (counted, replaced, before/after score + tier, delta, promoted, next, placement), season calendar (`currentSeason`, `daysLeft`, `nextSeasonWindow`, 56 days). |
| `limits.ts` | 15 runs STARTED per UTC day (quit and abandoned runs count), `utcDayStart`, `nextUtcDayStart`. UTC like the daily blindtest routes. |
| `timing.ts` | `validateAnswerTiming`: rejects not-a-number / negative (`invalid_time`), under 300 ms (`too_fast`), over 10 s (`over_round`), more time than the server saw + 250 ms (`ahead_of_server`); accepts with `effective = max(client, server - 1,500 ms)`; effective >= 10 s is a timeout. |
| `ladder.ts` | `compareStandings` (score, then average answer time, then who reached it first, then id), `rankLadder` (placed players only), `computeLegends` (top 100 of the ladder among Masters). |
| `select.ts` | `difficultyOf` (ranked accuracy once a song has 20 answers: >= 70% easy, >= 40% medium, else hard; before that the curated `songs.tier`: iconic/popular easy, medium medium, hard/unknown hard, none medium), `drawRankedSongs` (exactly 4/4/2, 10 different acts and titles, refuses rather than bends the mix), `drawRoundKinds` (6 song + 4 artist), distractors from the same pool (same generation + gender first; same act first for titles), `buildRounds`, `seededRng` for tests. |
| `run.ts` | Single-use run state machine: `newRun`, `startRound` (releases one round, stamps the server clip start), `answerRound` (locks the answer once, validates timing, reveals song + points), `finalizeRun` (10 answered = `submitted`, less = `quit`; an open round closes as a timeout). Refusals: `run_finished` (replay), `run_expired`, `out_of_order`, `round_open`, `not_started`, `already_answered`, `invalid_choice` + the timing reasons. |
| `service.ts` | Orchestration over a `RankedStore` interface: `issueRun`, `releaseRound`, `lockAnswer`, `submitRun`, `seasonCard`, `runNightly`, `liveSeason`. Starting a run quits any open one (recorded). Errors: `RankedNotLiveError` (503), `RankedRequestError` (status + code). |
| `db.ts` | `SupabaseRankedStore` (service role, new ranked tables + the `songs` read), missing relation / column / function codes map to `not_live`. Pool cached 10 min, seasons 60 s, per instance. Deezer previews refreshed at issue (4 s timeout, https only). |
| `http.ts` | Route wrapper: flag gate, read-only liveness probe, auth, error mapping, no-store, body parsers. Logs messages only, never bodies. |

## Data truths found (2026-09-25, read-only SQL)

- `ranked_plays` 0 rows, `bt_players` 0 rows.
- `songs` has NO accuracy columns (`times_played` / `times_correct` exist only on the legacy `blind_test_songs`).
  All 4,120 active songs have `play_count = 0` and `difficulty = 'medium'`. `blind_test_plays.choices` stats are
  keyed on legacy ids (0 match an active `songs` row). So "4/4/2 by community accuracy" can only use real
  accuracy once ranked answers accumulate (`ranked_song_stats`, 20 answers per song); until then the draw uses the
  curated `songs.tier` (active: iconic 369, popular 774, medium 1,351, hard 1,191, unknown 390, none 45).
- `ranked_plays` has `ranked_plays_insert WITH CHECK (true)` for PUBLIC (mig 059): anyone with the anon key can
  insert rows. The engine never reads scores from it.
- pg_cron is not installed.

## Rule choices made (the spec is silent; owner can flip any)

1. Timing is measured server side per round (15.4 "answer times are measured from the server clip start"):
   each round is released by `start` and locked by `answer`, so the client never holds the answers and a
   delayed answer cannot claim a fast time. Allowance 1.5 s for round trip + clip load, human floor 300 ms.
2. The daily limit counts runs STARTED, so quitting to re-draw songs still spends a run.
3. Starting a run quits any open run (recorded with the answered songs). Runs expire after 15 minutes and are
   closed as quit by the next start or the nightly job.
4. Only placed players (5 finished runs) are on the ladder; the card shows placement until then.
5. Tie-break "average answer time" = mean time of the right answers across the counted runs (weighted by right
   answers); then who reached the score first.
6. Ranked awards no XP in this pass (neither profile `award_xp` nor bt XP): the contract says ranked is a
   separate counter. See decision 4.
7. One run never repeats an act or a title (keeps options from giving each other away).
