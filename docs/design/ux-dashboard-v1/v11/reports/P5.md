## 5. Deviations from the prototype (and why)

1. Header copy (SEO lock): the live H1 "What's your quiz about?" and intro "No account needed to start. You can
   change everything later." (the server renders step 1); steps 2, 3 and done keep the live funnel's own headings
   and intros. The prototype says "Create a quiz" and a two-line intro. Owner decision 1.
2. The group field shows the focus look (pink border + halo) only when focused; the prototype hard-codes it.
3. Row actions on touch screens sit on the open row only; the prototype keeps them invisible but tappable on every
   row (hidden tap targets). Move up / Move down links in the open row (keyboard and touch reordering).
4. Words that must be true: step 2 status "N needs work" (any issue, not only answers); step 3 "question 4 is left
   out" and "Question 4 is not complete, so it will not be published." (the legacy publish sends only complete
   questions and clears the draft, so "stays in your draft" / "until you finish it" would be false); toast
   "Published" without an XP amount (the API returns none); "90 groups" (the hidden quarantine row is not offered).
5. "Add an image" only where the model has a picture (image quizzes; intruder has 4); the other types have no
   per-question picture, so the control would be dead.
6. Kept from the live funnel: the soft duplicate-title hint, the English-reach note for other languages, "Remove
   cover", the creator progress line, "Create another quiz", "Open your quiz" in a new tab, the username claim.
7. New copy: the Easy and Hard difficulty lines (the prototype has only the Medium one); "The group list did not
   load. Reload the page to pick a group." when the groups read fails.
8. The question and fun fact boxes grow with their text (a self-sizing textarea inside the prototype's box).
9. No autosave once published (see request 1: the legacy can re-save a cleared draft).

## 6. What is NOT verified, and why

- Real writes (create, uploads, username claim, share code, the magic-link email): production only, RUN-STATE
  owner decision 1. Proven by request shape (payloads recorded by the specs, bodies identical to the legacy in the
  unit parity tests).
- A real OAuth or magic-link round trip: no agent may sign in another way. The resume is proven with the test
  user's session on `?resume=publish` and with A0's pending action.
- An account without a profile: simulated by answering the profiles read with no row (the test user has one).
- A production build byte and JS comparison of the flag-off page (P5 compared dev renders, section 3.5).
- Browsers other than Chromium (drag and drop in Firefox gets `setData`, not run).
- The done state has no reference capture (`#pub-done` is not a capture state).
