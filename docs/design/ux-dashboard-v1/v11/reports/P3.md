  `/bts-quiz: read(s) failed (triviaAvailable, fanKnowledge, mvPulse, comments)`, same for `/ateez-quiz`,
  `/cortis-quiz`, `/chungha-quiz`, `/blackpink-quiz`. Before the fix those renders would have shipped "0 groups"
  or a hub without its trivia link, FAQ facts or side column, cached for the ISR hour.
- Build with the `/groups` read forced to fail (scratch copy only: a `P3_FAULT` switch in `read()`, never
  committed), `v11/reports/P3/seo-fix1/isr-fail-closed.txt`. `next build` with the read failing: the log says
  `[p3] /groups: read(s) failed at build (getGroupsDirectoryIndex); prerendered with a 60s revalidate`. The build
  passes and the route table shows `/groups` with a 1m revalidate (a good build has 1h). `next start` with the
  database back: one STALE response serves the degraded prerender, then a HIT on the regenerated page (intro, 90
  hub links, 1 h again). Next, the stored good page is aged past its hour and the server restarted with the read
  failing at request time. Two STALE responses both serve the good page (intro, 90 hub links). The log shows
  `FailedRenderError ... this render is not cached, the last good page stays`, and the file on disk is still the
  good page.
- Trade-off: a hub that has never been rendered and whose reads fail answers a 500 (nothing is cached; the next
  request renders it). The hubs have no build-time params, so this is the first visit after a deploy only.
- Hub, today's reads (open, request 2): the hub also reuses 10 of today's reads, and they swallow Supabase errors.
  They return `[]` / `0` / `null`, and `unstable_cache` keeps that for up to an hour. P3's gate only sees throws
  and timeouts, so it cannot catch these. It happened during this loop: the war map RPC failed once, and every
  flag-on hub lost its fandom war line and `/leaderboard#fandom-war` link until the dev cache was cleared. Flag off
  has the same exposure. The fix is in shared files outside P3's paths. It is ready as
  `v11/reports/P3/fail-closed-queries.patch` (each fetcher throws on `error`; the patch applies cleanly and
  type-checks), with the callers to check listed in `v11/requests/P3.md` request 2. Once applied, the v11 hub fails
  closed end to end with no P3 change.
- Not covered otherwise: a read that succeeds with wrong data cannot be detected.
