## 9. Owner decisions

1. Verse gates: `/community` lists the threads and blogs of the verse tables for every group, whatever
   `VERSE_PUBLIC` and `LIVE_SPACES` say (those gate the /verse product). One line in `lib/ux-v1/p8/feed.ts`
   if the community should follow `VERSE_PUBLIC` too (then the feed today is the debates only).
2. Daily debate rotation with the flag on: only the legacy `/leaderboard` community (CommunityContent) calls
   `ensure_daily_debate`. P8 never writes on a GET; if P9's leaderboard stops mounting CommunityContent, the
   daily debate stops rotating. Keep one ensurer (a cron or the page) when the flag goes on.
3. Apply `v11-p8-community.sql` (fan debates, challenge posts, hearts on threads / debates / replies).
4. Blogs keep the existing curator review (`submitted` until a curator features them) and need space
   membership (the editor asks the fan to Join, never joins silently). Blog covers: the essays route accepts
   only album art or space assets, so the editor has no cover upload; the card shows the group photo.
5. Closed daily debates in the feed: the last 3 that got votes (one a day would bury every thread).
6. The daily debate reply rides with the vote (the RPC stores one vote + one comment per fan per day), so the
   rail's one-tap vote (prototype) leaves no reply; the post view asks for the optional reply first.
7. `/community` and the post URLs stay noindex until you decide (they would duplicate /verse threads).
