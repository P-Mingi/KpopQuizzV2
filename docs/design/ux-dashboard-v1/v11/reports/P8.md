## 5b. Verse gates (privacy fail-closed)

Threads and blogs are Verse content (`verse_threads` + `verse_discussions`, `verse_essays` +
`verse_essay_reactions` + essay comments, space-asset covers). On `/community` they follow the same gates as the
/verse pages, through `lib/ux-v1/p8/verse-gate.ts`, which imports `verseHidden` and `spaceUnpublished` from
`lib/verse/visibility` (never edited):

| Rule | Where it applies |
|---|---|
| `VERSE_PUBLIC` not exactly `'true'` (`verseHidden`): no Verse-sourced item, and no Verse table is read | feed (threads, blogs: empty without a query), post view (`/community/thread\|blog/<id>` = 404 before any read), More from the community, pulse counts (threads + blogs count 0), Badge watch (Verse and cross-world badges hidden: they are earned through, or name, Verse activity), viewer route (blog hearts not read), like route (thread / comment targets = 404 before any write), Blogs tab removed, Thread and Blog editor modes removed (and the composer hides when no mode can post: no dead door), a compose URL for a Verse mode opens nothing |
| A parked space (`spaceUnpublished`: any slug outside `LIVE_SPACES`, today `bts` only), whatever `VERSE_PUBLIC` says | feed queries filter `group_id IN (live group ids)` (the ids are a cache-key argument, so no cache entry outlives a gate change) and `gateVersePosts` filters again outside every cache; post view 404 before the replies are read; pulse counts live spaces only; like route resolves a thread or comment (thread or blog) to its space; the Thread / Blog group picker lists live spaces only ("No open fandom space matches."), debates keep every group |
| A Verse item without a known group | not shown (fail closed) |

- Play-side content is unaffected: daily debates, fan debates, challenges, Happening now (activity events),
  play badges, the fandom war.
- No viewer bypass on `/community`: its renders and data caches are shared between viewers, so a privileged
  render could reach anyone through a cache. The owner reaches hidden or parked content on /verse, where the
  admin bypass (`isVerseAdmin`) lives. (The /verse pages themselves use `isVerseAdmin` for both gates.)
- Existing Verse write routes (`/api/verse/threads`, `/essays`, `/discussions`, `/essays/reactions`, `/flags`)
  do not check the gates themselves (not P8's files); P8 never offers them for gated content.
- Proof: `src/lib/ux-v1/p8/verse-gate.test.ts` (9 tests; env per test with `vi.stubEnv`, a recording fake
  database): decisions for `'true'`, `'false'`, `''`, `'TRUE'`, `'1'`; hidden = feed and post read no Verse table
  at all; open = the thread query carries `in('group_id', [live ids])` and a parked row that slips through is
  dropped; a parked thread or blog is a 404 and its replies are never read; a live thread renders; badges;
  editor modes. A mutation check (gates removed) makes 3 of them fail. e2e: section 7 ("Verse gates").
- Today's production data: 3 threads and 1 blog, all BTS (live), so with `VERSE_PUBLIC=true` the feed is
  unchanged; with it off the feed shows the daily debates only. No parked-space Verse row exists yet, so the
  parked case is proven by the unit tests and the query filter, not by a real row in e2e.
